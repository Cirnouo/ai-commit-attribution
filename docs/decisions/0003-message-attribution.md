# Message attribution and explicit continuation handoffs

Status: accepted for schema-1 message rendering and validation.

Status update 2026-10-15: [0004](0004-agent-policy-discovery.md) supersedes only
the scanner ownership, scan/candidate associations, binding and stale-routing
requirements below. MessageAssessment and message results now use schema 2;
assessment sources explicitly identify a message record or declared
automatic-signing reference. Isolated trailer interpretation, byte preservation,
exclusive routing, exact signature migration and scoped exception safeguards
remain applicable. Read the historical schema-1 account below in that context;
it is not current schema-2 acceptance evidence.

The same fresh policy scan owns scope/evidence and candidate identity. Message
commands call its routing check before a lazy default-data boundary. Exclusive
repository-policy results remain unverified exit-10 handoffs; an unusable ledger,
assessment or registry cannot affect that branch. No general repository validator
or second scope/identity owner is introduced.

Git trailer semantics and exact source-byte preservation have separate jobs.
The observer's exact read-only argv allowlist stays intact. A dedicated process
uses trusted Git in an isolated non-repository temporary directory; a conservative
span mapper preserves original prose/unrelated records while reconciling owned
records. Ambiguous raw/Git layouts fail instead of silently normalizing bytes.
Explicit output creates an absent leaf exclusively and never replaces an input.

A PR4 user exception's free text is insufficient to mechanically request
continuation. A narrow current MessageAssessment may explicitly apply exact
existing exception reference/operation/issue IDs with the documented action
continue-with-incomplete-disclosure. The application keeps all original summary
issues, evidence and exit 20. Only the outer message goal can complete with a
separately reported incomplete-with-user-exception state. Signature conflicts,
raw input/path safety and stale routing cannot be waived this way.

This mirrors the narrow existing signature migration handoff. It is a declaration
that an integrator inspected a genuine current user decision, not a trust boolean,
authentication mechanism or grant of Git operation permission. The integrator
must actually verify provenance and authority; the CLI cannot establish those
facts. The installed authoritative before-use contract is packaging/messages.md.
Complete host/question orchestration and real acceptance remain separate work.

The existing shared record identity owner now distinguishes model punctuation
from Agent delimiters and effort syntax. Formal IDs such as AWS's documented
[amazon.nova-micro-v1:0](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-amazon-nova-micro.html)
retain their colon exactly (primary source checked 2026-10-14). This is a compatible
schema-1 input extension, not a model catalogue, dispatch claim or provider
integration. The repository footer checker already accepts colon-bearing values
and remains unchanged; source summary/mapping and installed message parity are tested.

Partial successor accepted 2026-10-15: [0005](0005-planned-commit-ledgers.md)
replaces event joins with schema-3 identity-key assessments and removes the
scoped exception application/incomplete-with-user-exception completion path.
It adds forward preparation receipts and exact-result reconciliation. Isolated
trailer interpretation, byte preservation, exclusive policy routing and exact
signature classification/migration authority safeguards remain. This is an
accepted design change, not implementation or test evidence; the preceding
schema-1/schema-2 accounts and observed results retain their historical scope.
