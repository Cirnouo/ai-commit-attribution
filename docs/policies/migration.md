## Technical adaptations

One generated Node ESM Skill bundle replaces dual-host plugin delivery. Owned
TS stays in source; future packaging input and installed payload trees are
separate. Root package version owns generated metadata. esbuild metafile notices,
independent exact output inventories and external runtime execution replace
browser/plugin product smoke. The audit bundle has its own inventory; extra
files must fail its check too. Browser upstream delivery/fingerprints are removed,
while the target's own graph/config/source evidence is checked.

Tool versions follow the source baseline; skills 1.7.2 is added to the same audit
graph. YAML uses a real parser and all-document pnpm lock parsing. Owned filenames
now use .yaml with the sole exact GitHub chooser exception. Biome cannot establish
Python, Markdown or YAML coverage. Source-specific style/lint domain exceptions
are reviewed as local technical choices rather than inherited product policies.

Coverage gates come from this repository's first measured governance suite,
not the source percentages. New check contexts are promoted only after success;
browser/C# lanes are replaced by actual Skill/JavaScript verification.

## Project-specific exclusions

Do not copy CDP, MCP, Chrome/Obsidian target ownership, native launch/elevation,
browser data directory leases, transport/session routing, official tool catalogs,
embedded Chrome server delivery, plugin manifests, dual Codex/Claude marketplace
distribution or their smoke requirements. Their scopes and ADRs are not target
governance. Do not copy source coverage percentages or stale workflow registrations.

## Observed platform settings

The source's public main, issue/fork features, disabled wiki/projects/discussions/
downloads/pages, squash PR_TITLE/PR_BODY, read-only Actions/no PR approval, first
external contributor approval, security toggles, immutable Releases and strict
main Ruleset are observed platform configuration. Target read-back records actual
values separately. Source has advanced CodeQL, not default setup. Main's Ruleset
exists even when classic branch protection reports 404. No bypass is migrated.

The source Release workflow creates notes automatically; it does not rewrite
Changelog or bump versions. Both that automation and immutable Release settings
are migration obligations. Implementation is staged in PR3 without creating a
tag/Release during this task. Required target checks exclude source browser and
C# contexts. Live source settings may evolve without changing the fixed policy
baseline used here.
