## Technical adaptations

One generated Node ESM Skill bundle replaces dual-host plugin delivery. Owned
TS stays in source; future packaging input and installed payload trees are
separate. Root package version owns generated metadata. esbuild metafile notices,
independent exact output inventories and external runtime execution replace
browser/plugin product smoke. The audit bundle has its own inventory; extra
files must fail its check too. Browser upstream delivery/fingerprints are removed,
while the target's own graph/config/source evidence is checked.

Tool versions follow the source baseline; skills 1.7.2 is added to the same audit
graph. YAML uses a real parser and all-document pnpm lock parsing. Owned filenames
now use .yaml with the sole exact GitHub chooser exception. Biome cannot establish
Python, Markdown or YAML coverage. Source-specific style/lint domain exceptions
are reviewed as local technical choices rather than inherited product policies.

Coverage gates come from this repository's first measured governance suite,
not the source percentages. New check contexts are promoted only after success;
browser/C# lanes are replaced by actual Skill/JavaScript verification.

## Issue governance adaptation

The fixed source Issue policy, Markdown semantics, feedback state machine,
REST boundary, queue/security workflow and their semantic tests are adopted in
PR2. Bug fields now describe this attribution Skill, Agent host and Node/Git
versions; CDP/application diagnostics are excluded. Other is a host choice, not
a promise of verified loading. Forms/workflow use .yaml; only GitHub's chooser
keeps config.yml and is explicitly included in configuration fingerprints. The
form parser uses the target's shared YAML1.2/core profile.

Current classification labels and the diagnostic label are separately
provisioned platform state. Offline API fixtures do not prove a live Issue
publication. REST's final compare-and-set gap and queued-event recovery remain
explicit in the authoritative typed Issue policy.

## Release governance adaptation

The fixed source tooling/release.ts, tooling/version-policy.ts,
.github/workflows/release.yml and their release/version/workflow tests provide
the PR3 state-machine baseline. The target uses release.yaml/ci.yaml, shared
errors.ts and owned-yaml.ts, and compares only root/tag/final generated Skill
versions. Dual-host Plugin paths, CDP payload/license logic and packaging owners
are excluded. The production final Skill is required but is not created by this
governance PR. Real final-layout fixtures exercise publication and persisted-draft
recovery; real Git fixtures separately prove annotation and ancestry behavior.

The target additionally rejects noncanonical snapshot headings and conflicting
matching Releases across all discovery pages. Release REST preserves HTTP status
for explicit HTTP 404 handling without changing the Issue adapter. The actual workflow
extends the existing .github/**/*.yaml configuration fingerprint boundary.
GitHub latest stable/legacy selection and the original annotated push-object gate
are retained. Their live evidence limits and prepublication obligations are owned
by the [release policy](releases.md), not inferred from local test success.

Commit types/scopes have one dependency-free owner, tooling/commit-vocabulary.ts.
The current commitlint configuration reads that data directly instead of loading
Git and release validators through governance.ts; governance preserves its public
constant exports. Real config isolation and the existing vocabulary/footer tests
cover this dependency-boundary adaptation.
