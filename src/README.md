# Attribution runtime

records.ts owns schema validation and shared supplied-scope canonicalization.
parseOperationShape preserves portable historical declarations without filesystem
observation; parseOperation additionally enforces physical local directories for
current scope. Portable shapes never authorize a current Git action.
summarize.ts normalizes confirmed identities, deduplicates exact tuples and
reports declared blockers. attribution.ts exposes ledger commands, prepare/finish, summarize, render and validate,
and locates its installed registry from import.meta.url. Source requires no
runtime packages.

ledger-contract.ts owns the versioned worktree state and its independent 16 MiB
bound. ledger-store.ts resolves actual Git context, preserves the shared exclude,
and publishes locked state transactions with exact-byte/version checks. ledger.ts
owns explicit selection, revisions and lifecycle transitions; ledger-cli.ts parses
the command group and loads the registry only for identity mutations. The installed
state contract is packaging/ledgers.md. ledger-transfer.ts owns strict portable
bundles, recoverable export phases, resume/copy import, explicit original-move
rebind, removal coverage and terminal cleanup. Historical preparations and sealed
results retain their original declarations across context moves; portable parsing
never grants current action authority. Store rebind/prune/import entries are
narrow, while ordinary transforms cannot change locators or delete records.
result-contract.ts owns pure historical ResultPlan and PreparedReceipt parsing,
including ordered object references, candidate bytes and digests. result-review.ts
owns pure ResultReview and SealedResult declarations and their exact ID/hash
joins. Neither historical parser observes the filesystem or authorizes a new action.
result-git.ts owns bounded read-only index/tree/result observation through fixed
trusted Git queries, raw index parsing and complete manifest/tree comparisons.
ledger-preparation.ts owns candidate-before-state preparation and exact-result
sealing, frozen identity/policy boundaries, explicit caller review and idempotent
recovery. ledger-preparation-cli.ts parses their top-level commands and loads
only consumed default evidence. Lazy loaders record their actual consumed paths
for publication protection. packaging/ledgers.md owns their installed contract.
state-path.ts owns matching the reserved raw Git path namespace, including case
variants on Windows/macOS and Windows stream, trailing-character and short-name aliases.

The maintained identity and policy contracts are packaging/records.md and packaging/policy.md.
input-contract.ts owns the shared 2 MiB input bound and strict object/string-list
validation. runtime-support.ts owns deterministic serialization and reusable
safe physical path observation. policy-contract.ts owns the schema 2 decision
and internal route types. policy.ts accepts an Agent semantic decision, checks
its normalized declared Operation against the supplied Operation, and selects
one of three exclusive branches. It does not discover policy or observe Git state.
Repository-policy and needs-decision paths never import default summary or read
the installed registry, ledger or assessment.

message.ts adds route-first render/validate with a lazy default-input boundary.
message-contract.ts owns their result types; message-assessment.ts checks exact
current signature/migration joins using full identity keys. message-trailers.ts runs isolated
Git interpretation and reconciles owned byte spans. message-output.ts creates
only safe absent new files and owns ordinary-output checks excluding Windows
streams/device namespaces, shared by ledger export. output-scope.ts locates actual Git administrative
directories only for explicit new-file output protection. safe-git.ts restricts
location and ledger-initialization observations to fixed query forms, with trusted executable,
environment, time and network boundaries. packaging/messages.md owns the
installed contract. The SafeGit allowlist does not include trailer processing.
Only the shared trailer temporary parent uses physical directory identity checks;
private trailer directories and individual files retain strict metadata checks.
